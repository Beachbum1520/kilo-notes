## Known data limitations (accepted, do not re-debug)
- **Treadmill distance = watch stride estimate, not Scott's calibrated value.** Scott uses "calibrate and save" on the watch after every treadmill run (enters the treadmill console distance). Garmin Connect keeps the corrected summary, but the TCX FitnessSyncer exports carries the ORIGINAL watch-estimated lap distances (~8% high on the verified sample: June 28 run = 4.73 mi in Connect, 5.1 mi in WattsWay; durations match exactly). Decision: live with it. Error is one-directional and shrinks as the watch's stride model learns from his calibrations. An in-app distance-edit feature belongs with goal setting / plan builder (roadmap #3–4), where trusted distance starts to matter.
- **Identical avg HR across easy treadmill runs is real, not a bug.** Zone 2 discipline converges (four runs at exactly avg 117, verified against Connect). Per-file max_hr values differ, proving per-file parsing.

## The workflow (established, use it)
1. Build tasks run as **Cursor cloud agents** (cursor.com/agents): every task prompt starts "Work on a new branch called `<name>` and open a pull request — do NOT push to main."
2. Scott reviews the PR on GitHub (Files changed shape-check), marks ready, merges → Vercel auto-deploys.
3. **One agent at a time** — no parallel agents touching the same files.
4. Edge functions deploy MANUALLY via Supabase dashboard editor (no CLI on his machines). **The recipe (memorize):** Deploy new function → Via Editor → Add File `_shared/cors.ts` (paste from GitHub raw) → Add File `_shared/supabaseClient.ts` (paste, then replace line 1 with `import { createClient } from "npm:@supabase/supabase-js@2";`) → index.ts: paste function code, change `../_shared/` imports to `./_shared/` → type function name LAST (field clears when adding files) → Deploy. Errors seen: "slug invalid" = name field cleared; "Module not found ../_shared" = fix import dots; "Module not found /_shared" = missing dot before slash (must be `./_shared/`); "Relative import @supabase" = the npm: line 1 fix; "Module not found ./_shared" = file missing/misnamed in FILES panel (filenames are CASE-SENSITIVE — supaBaseClient ≠ supabaseClient).
5. **Function REdeploys are lighter:** the _shared files persist in the editor. Open the function → replace index.ts contents only → fix the two imports to `./_shared/` → confirm name field → Deploy. Full three-file recipe is only for functions that don't exist yet.
6. SQL runs manually in Supabase SQL Editor (paste from GitHub raw migration files).
7. **Redeploy source rule:** always copy index.ts from GitHub raw on main AFTER the PR is merged, never from a branch. Merge order: agent finishes → review diff → MERGE → Vercel deployment Ready → then redeploy function. (Skipping the merge before redeploy shipped stale code once.)
8. Follow-ups to a running agent go in the agent's conversation at cursor.com/agents — plain GitHub PR comments do NOT reach it.
9. When a cloud agent independently designs something better than the spec (e.g. per-user folder IDs), evaluate on merits rather than reflex-reverting — but make it complete the original spec's untouched parts (it silently dropped the Settings card once).
